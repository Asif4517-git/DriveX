12. OPEN-SOURCE GAME DISCOVERY
Research date: 2026-11-06. These are ten candidates, not ten independently
validated playable games. GitHub API checked each LICENSE file and latest push
date; a recent push is only an activity signal, not proof of support. All are
MIT code licenses; retain copyright and license notices. Verify every asset,
dependency and trademark separately, even where the repository says MIT.
Graphics, modes and handling below are upstream claims or limited source
inspection; no normal-desktop gameplay, visual fidelity or performance test
was possible. Integration effort is an estimate, not an actual trial.

1) LibreCorsa — https://github.com/KhazP/librecorsa
Demo: https://librecorsa.org/ (page extraction reached ready screen; no input).
TypeScript, Next.js/React, Three.js WebGL2; code LICENSE MIT, pushed Nov 6
2026. Upstream describes actual imported 3D cars, 500 Hz physics, suspension,
thermal tires, AI, circuits and P2P multiplayer; source tree includes src/lib,
components and verification scripts. Physics realism/claims not independently
measured. Track-focused, not a complete open-world game. Strong physics and
race-system candidate, but integration is high effort. README separately lists
Mercedes-AMG GT3 CC BY-NC-SA 4.0 and some public assets restricted to
noncommercial/educational use; 2026 car CC BY 4.0. Audit every asset and
replace incompatible ones before commercial distribution; trademarks too.

2) Nurburgring Drive — https://github.com/esc5221/drive-game
Demo: https://drive-game.pages.dev/ (not opened interactively). JavaScript,
Three.js, custom 240 Hz physics; LICENSE text says MIT for code despite GitHub
API classifying whole file NOASSERTION; pushed July 10 2026. README describes
imported real 3D vehicles, suspension, tires, weather and real tracks. Source
folder lists physics.js, car.js, rain.js and net.js; functionality untested.
Reuse code only after license review; OSM-derived track data ODbL, Porsche
model CC BY-SA 4.0 and Hyundai CC BY-NC 4.0, per credits. Track/data share-alike
and noncommercial restrictions require careful segregation or replacement.
High effort to adapt beyond circuit driving; project calls itself fan/noncommercial.

3) CarRace — https://github.com/alexander-uspenskiy/CarRace
Demo: https://alexander-uspenskiy.github.io/CarRace/ (extraction reported
module-fetch failure; no gameplay test). JavaScript/Three.js, MIT LICENSE;
pushed Oct 15 2026. Source tree separates src/sim (carPhysics, AI, collisions,
tyres) and render. README claims procedural 3D Formula cars, three tracks,
19 AI drivers, garage upgrades, saved records and synthesized sound. Candidate
for race-flow, UI and AI; stylized procedural vehicles, not realistic licensed
car meshes; physics quality not measured. Medium-high integration; Formula
brand/team names and liveries require independent trademark/IP clearance.

4) Overdrive City — https://github.com/appleweiping/overdrive-city
Demo: https://appleweiping.github.io/overdrive-city/ (HUD extracted only).
JavaScript, Three.js, MIT LICENSE; pushed Oct 23 2026. Source inspection found
traffic.js implementing lane directions/intersection choices and imports of
Vehicle; README describes procedural 3D city, vehicles, traffic and day/night.
Promising open-world architecture and traffic, not verified handling or asset
quality. Simple stylized cars and acknowledged limited physics need replacement
for realism. Medium-high effort; Three.js also MIT, check all notices.

5) Raycast RC Car — https://github.com/icurtis1/raycast-vehicle
Demo: https://raycast-rc-car.netlify.app/ (not played). JavaScript, Three.js,
cannon-es; MIT LICENSE; pushed July 6 2026. Direct inspection of src/Vehicle.js
found GLTFLoader, CANNON.RaycastVehicle, setSteeringValue, applyEngineForce
and setBrake calls, plus body and separate wheel GLB imports. This is evidence
of a 3D vehicle/physics implementation in source, NOT evidence it runs well.
README describes arcade RC handling, suspension rays, GLB level and controls.
Useful compact physics/controller example; needs realistic vehicle dynamics,
world and content. Medium adaptation; verify GLB asset provenance separately.

6) Sketchbook — https://github.com/swift502/Sketchbook
Demo: https://jblaha.art/sketchbook/latest (not played). TypeScript, Three.js,
Cannon.js, MIT LICENSE; archived, last push Oct 10 2024. README describes 3D
playground and Blender scene workflow with vehicles/characters, not a finished
racing game. Reuse architectural ideas and code with notice; independently
check asset licenses. Older dependencies, archived maintenance, and limited
racing systems make integration high effort. Actual cars and controls untested.

7) Racing Games — https://github.com/monon98/racing-games
Demo: https://monon98.github.io/racing-games/ (not played). TypeScript/Vite,
Three.js, cannon-es; MIT LICENSE; pushed Nov 4 2026. README describes
procedurally generated 3D car, four-wheel suspension, two track modes, GLB

Potential prototype for tracks and physics; replace simple visuals, add AI

8) Neon Drive — https://github.com/evildevill/car-game

Oct 28 2026. README describes procedural car-shaped 3D geometry and city,

9) RPG Car Game — https://github.com/rsamwilson2323-cloud/rpg-car-game
Demo: none identified. HTML/JavaScript, Three.js WebGPU and Rapier; MIT

10) ThreeJS SimpleCarPhysics — https://github.com/juwalbose/ThreeJS_SimpleCarPhysics
Demo: https://c9.io/juwalbose/threejs_simplecar (linked upstream; not played,

RECOMMENDATION AND COMPATIBILITY
LIMITED — Best provisional overall starting point for realistic track racing:
LibreCorsa, because its documented physics, AI and modular ecosystem are much
closer to the goal than a blank renderer; this is NOT a gameplay or quality
endorsement until independently tested and its noncommercial assets removed or
cleared. If DriveX's primary priority is an open city rather than sim racing,
Overdrive City is a better conceptual city/traffic starting point, but its
handling and visuals need major replacement. Choose only after hands-on trials.
LIMITED — Best physics candidate: LibreCorsa based on its documented models
and validation claims; compare experimentally with Nurburgring Drive and
Raycast RC Car before adopting. Physics accuracy remains unverified.
LIMITED — Rendering foundation: Three.js/WebGL is common to most candidates
and has wide ecosystem potential, but WebGL performance/support here is
untested. Babylon.js and WebGPU were not comparatively tested.
LIMITED — Candidate assets: Kenney Car Kit https://kenney.nl/assets/car-kit
is listed as CC0 on the official asset page; suitable as stylized placeholders,
not photoreal cars. No pack downloaded or inspected. LibreCorsa credits a CC
BY 4.0 open-wheel model; confirm original source, license/version, attribution,
modifications and branding before reuse. No realistic commercial-safe car
library has been independently verified.
LIMITED — MIT code from these projects may generally be modified/combined with
license notices; merge at clearly defined interfaces, not by assuming identical
coordinate systems, timesteps, input, cameras or engine versions. In particular,
choose one authoritative vehicle physics simulation and adapt traffic/renderer
around it; do not run two vehicle solvers together blindly. Separate ODbL,
CC BY-SA and noncommercial assets and check distribution obligations and
trademarks. This is not legal advice.

Substantial work remains: evaluate playable baselines and licenses; implement or
adapt a city, road/terrain streaming and AI; author/clear realistic vehicles,
interiors and audio; tune handling and cameras; build garage, progression and
UI; add weather, persistence and optional multiplayer; optimize and test across
real browsers and hardware. None of the listed projects was imported or modified.
